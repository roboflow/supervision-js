# Basketball SAM3 Fixture

This fixture is the default basketball demo fixture. It pairs deterministic SAM3
detections with the exact normalized media file used for frame extraction:

```text
basketball_sample.normalized.webm
detections.manifest.json
detections/*.json
```

The WebM is already normalized to 1920x1080 video at 30 fps with no audio. The
demo should load it directly; no browser-time media normalization or transcoding
is needed for this fixture.

## Generation

The fixture was generated by running SAM3 on frames extracted from
`basketball_sample.normalized.webm`, then converting the output into the
`supervision-js` demo detection timeline format. The generated prompts were:

- `white team player`
- `yellow team player`
- `basketball`

`raw-sam3.jsonl` is kept beside the normalized fixture for provenance. It
contains the SAM3 request and response records with no image payloads and no API
key. `detections.json` is the full normalized source timeline. The demo runtime
loads `detections.manifest.json` first, then fetches one-second chunks from
`detections/` on demand so the hot buffer does not need the full timeline in
memory.

## Frame Semantics

The fixture contains 270 frame slots for a 9 second video at 30 fps. Frame
indexes are the deterministic 30 fps slot identity, but `mediaTime` stores the
actual decoded WebM sample timestamp. Those timestamps are rounded to WebM's
millisecond timebase, so they follow a `0.033`, `0.034` duration pattern rather
than exact recurring thirds.

```text
frameIndex = deterministic 30 fps slot
mediaTime = decoded sample timestamp
endTime = mediaTime + decoded sample duration
```

Valid frame indexes are `0` through `269`. The renderer uses
the `mediaTime` / `endTime` interval as the sync source of truth. `frameIndex`
is retained only as metadata for diagnostics and fixture review.

Frames were extracted by sampling the center of each 30 fps slot. This avoids
selecting the previous decoded sample at slot boundaries where WebM millisecond
timestamps and `0.034s` durations overlap the next ideal frame boundary.

## Masks

Detections include SAM3 masks encoded as COCO-style compressed RLE:

```json
{
  "encoding": "compressedRle",
  "width": 1920,
  "height": 1080
}
```

Boxes are derived from those 1920x1080 masks and are stored in the same media
coordinate space.
