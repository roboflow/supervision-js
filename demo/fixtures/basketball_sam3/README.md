# 9s Basketball Sample Fixture

This fixture keeps SAM3 detections generated from a normalized 30fps WebM
timeline. The source MP4 runs at 25fps, so its frames land on the 30fps
detection grid only every fifth frame; the demo therefore plays the proxy
declared as `media.proxyFile` in `fixture.meta.json`:

```text
../basketball_sample/proxy-30fps.webm
```

Detections load from committed chunks rather than calling SAM3 at runtime.

## Files

```text
fixture.meta.json
detections.manifest.json
detections/*.json
detections.json
raw-sam3.jsonl
basketball_sample.normalized.webm
```

`basketball_sample.normalized.webm` is retained as provenance for the original
fixture generation and sync checks. `../basketball_sample/proxy-30fps.webm` is
what the demo plays; `npm run fixture:sam3:proxy` rebuilds it and lands the same
270 frame timestamps this file carries.

## Generation

The fixture was generated by running SAM3 on frames extracted from a normalized
30fps WebM version of `basketball_sample.mp4`. The prompts were:

- `white team player`
- `yellow team player`
- `basketball`

`raw-sam3.jsonl` contains SAM3 request and response records with no image
payloads and no API key. `detections.json` is the full normalized source
timeline. The demo runtime loads `detections.manifest.json` first, then fetches
one-second chunks from `detections/` on demand so the hot buffer does not need
the full timeline in memory.

## Frame Semantics

The fixture contains 270 frame slots for a 9 second video at 30fps. Frame
indexes are deterministic 30fps slot identities, while `mediaTime` stores the
actual decoded WebM sample timestamp.

```text
frameIndex = deterministic 30fps slot
mediaTime = decoded sample timestamp
endTime = mediaTime + decoded sample duration
```

Frames were extracted by sampling the center of each 30fps slot. This avoids
selecting the previous decoded sample at slot boundaries where WebM millisecond
timestamps and `0.034s` durations overlap the next ideal frame boundary.

## Masks

Detections include SAM3 masks encoded as COCO-style compressed RLE:

```json
{
  "encoding": "compressedRle",
  "width": 1920,
  "height": 1080
}
```

Boxes are derived from those 1920x1080 masks and are stored in the same media
coordinate space.
